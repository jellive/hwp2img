# 드롭존 창 추가 — 계획 + 레인 지적 처리 원장 (2026-08-24)

## 무엇을 만드나

exe 를 **인자 없이 실행**했을 때(어머니가 바탕화면 아이콘을 더블클릭했을 때)
"이곳으로 한글 파일을 끌어오세요" 창을 띄우고, 탐색기에서 .hwp 를 그 창에 떨어뜨리면
자동으로 변환한다. **기존 "아이콘 위에 드롭" 경로는 그대로 살아 있다** — 인자가 있으면
창은 뜨지 않고 지금과 완전히 같이 동작한다.

즉 지금 argv 0개일 때 나오던 "이 프로그램 위로 끌어다 놓아 주세요" **에러창을 대체**하는 것이다.
막다른 길 하나를 없애는 변경이고, 이미 동작하는 경로는 건드리지 않는다.

## 추가 — `launch()` 본문이 미검증이던 구멍을 닫았다 (2026-08-24, 같은 날 후속)

**발견:** 커밋 `eb9cb0a` 시점에 테스트의 `launch` 참조는 **전부 주입한 가짜이거나
monkeypatch 한 스텁**이었다. 즉 진짜 창을 만드는 코드 — `tk.Tk()`, 위젯 생성,
`root.protocol`, `filedialog`, `_TkView`, `root.after` 마샬링 — 는 **한 줄도 실행된 적이
없었다.** 위젯 인자 오타 하나가 어머니 PC 까지 갔을 것이고, `--noconsole` 이라 거기서는
에러 메시지조차 안 보이고 디버그도 불가능하다.

**한 것:**
1. `brew install python-tk@3.14` — venv 파이썬(3.14)에 Tk 9.0 을 붙였다.
   (`/usr/bin/python3` 에는 원래 Tk 8.5 가 있었지만 PyMuPDF·Pillow 가 없어 못 쓴다.)
2. `launch()` 를 `_build_window()` + `launch()` 로 쪼갰다. `mainloop()` 을 부르지 않고
   창을 돌려받을 수 있어야 테스트가 가능하다. **동작 변경은 없다.**
3. `tests/test_dropzone_window.py` — 진짜 Tk 창으로 도는 스모크 테스트 10개.

**이 과정에서 변이 검사가 내 테스트의 결함 2건을 잡았다** (테스트가 먼저 전부 초록이었다):

| 결함 | 무엇이 문제였나 |
|---|---|
| fixture 가 `except tk.TclError: skip` 이었다 | **디스플레이 없음**과 **위젯 인자 오타**가 둘 다 `TclError` 다. 통째로 skip 하니 `justify`→`justfy` 변이가 **skip 으로 초록**이 됐다 — 잡으려던 바로 그 결함을 못 잡는 테스트였다. → 디스플레이 실패 문구일 때만 skip, 나머지는 `raise` |
| `assert root.protocol("WM_DELETE_WINDOW")` | Tk 는 **등록을 안 해도** 기본값(`…destroy`)을 돌려준다. 참/거짓 검사로는 등록 여부를 못 가른다 → 등록된 핸들러를 **실제로 호출**하고 창이 닫혔는지로 판정 |

**부수 실측 (Mac 한정, 코드 결함 아님):** pytest 프로세스에서 Tk root 를 만들었다 부수고
다시 만들면 `update_idletasks` 에서 **세그폴트**했다. 프로세스당 root 하나로 간다
(모듈 진입 때 프로브 root 를 띄우던 방식을 뺐다). 실앱은 root 를 하나만 만든다.

**결과:** 테스트 85 → **95**. 변이 검사 누계 **22종 전부 FAIL 확인**.
Tk 배선은 이제 검증됐다 — Windows 에서 창이 안 뜨면 원인은 **배선이 아니라 패키징**이다.
