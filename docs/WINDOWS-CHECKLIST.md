## A. watchdog — 어머니 PC 금지선 (5항목)

**이 프로그램의 제1 제약은 "어머니가 열어둔 한글 문서를 절대 죽이지 않는다" 다.**
codex 리뷰 2회로 BLOCKER 1 + HIGH 1 + MEDIUM 2 를 잡아 고쳤지만
**Windows 에서 실행해 본 적은 한 번도 없다.**

먼저 읽을 것: `src/hwp2img/watchdog.py:1-32` 독스트링 · `WINDOWS-HANDOFF.md` 의 "1-2" 절.

### [ ] A1. 열려 있는 한글을 죽이지 않는다 ← **여기서 실패하면 나머지는 의미 없다**

- **하는 법** — 한글을 먼저 띄워 문서를 하나 열어 둔다 → 작업 관리자에서 그 `Hwp.exe` 의
  **PID 를 적어 둔다** → 별도로 멈추는 hwp(암호 걸린 것이면 된다)를 변환기에 넣는다 →
  30초 타임아웃을 기다린다.
- **통과** — 먼저 띄운 한글 창과 문서가 그대로 살아 있고, **적어 둔 PID 가 작업 관리자에 그대로 있다.**
- **실패하면** — 즉시 멈추고 보고한다. 설정 문제가 아니라 설계 결함이다. 어머니 PC 에 아무것도 올리지 않는다.

### [ ] A2. 암호 걸린 hwp → 30초 안에 안내창 *(아직 아무도 못 해본 케이스)*

- **하는 법** — 실제 암호 걸린 .hwp 를 넣는다.
- **통과** — **30초**(`watchdog.py:49` `DEFAULT_TIMEOUT_SECONDS = 30`) 안에
  "이 파일은 변환할 수 없어요…" 안내창이 뜬다. 기다리는 동안 다른 프로그램이 정상 동작한다.
- **실패하면** — 안내창 없이 멎기만 하면 A1 과 같은 급이다. 시간만 모자라면 A5 로 간다.

### [ ] A3. 타임아웃 뒤 **우리 파이썬 자식**이 죽는다 — 고아 `Hwp.exe` 는 **세어서 기록만** 한다

🔴 **이 항목의 통과 기준이 2026-08-18 에 뒤집혔다. 옛 기준("`Hwp.exe` 가 사라지나")으로 재지 마라.**
`watchdog.py` 의 `_kill()` 은 **우리가 만든 파이썬 자식만** 죽이고 `Hwp.exe` 는 **일부러
안 죽인다** — PID 재사용 때문에 소유권을 증명할 수 없고, 그게 A1 을 깨뜨리는 경로다.
즉 **고아 `Hwp.exe` 가 남는 것은 정상이고 설계된 동작이다.**

- **하는 법** — A2 직후 작업 관리자에서 ①우리 exe 의 파이썬 자식이 사라졌는지
  ②`Hwp.exe` 가 **몇 개** 남았는지(A1 에서 적어 둔 PID 는 빼고) 센다.
- **통과** — 파이썬 자식이 남지 않는다. `Hwp.exe` 개수는 **통과/실패가 아니라 숫자를 여기 적는다**:
  `남은 Hwp.exe: ___개`
- **그 숫자가 쌓여서 실제로 문제가 되면**(재부팅 없이 메모리를 계속 먹으면) 그때
  `watchdog.py:30-31` 이 적어 둔 **핸들 기반 종료**(`GetWindowThreadProcessId` → `OpenProcess`)를
  Windows 에서 작성·검증해 넣는다. **PID 스냅샷 비교로 되돌리지 마라.**

### [ ] A4. onefile exe 에서 자식 프로세스가 실제로 뜬다

- **하는 법** — 따로 할 게 없다. **변환이 한 번이라도 성공하면 이 항목은 통과다** —
  `cli.py:115` 가 변환을 통째로 `watchdog.run_process_file` 에 넘기고, 그게 spawn 으로
  자식을 띄운다. 변환이 됐다는 것은 자식이 떴다는 뜻이다.
- **통과** — 변환 성공. 자식이 `python.exe` 를 새로 찾으려다 실패하는 형태의 에러가 없다.
- **실패하면** — `run.py:12` 의 `multiprocessing.freeze_support()` 가 onefile 에서 안 먹은 것이다.
  codex 2차 리뷰는 최신 PyInstaller 가 이미 풀린 `_MEIxxxx` 를 재사용한다고 봤지만
  **이 exe 로 확인한 적은 없다.**

### [ ] A5. 페이지 많은 문서에 30초가 충분한가

- **하는 법** — 페이지 많은 .hwp 를 변환하고 걸린 시간을 잰다. (실측 기준선: 보통 문서 4~6초)
- **통과** — 30초에 여유 있게 들어온다. `걸린 시간: ___초`
- **실패하면** — **정상 변환이 타임아웃으로 오판되는 것도 실패다.**
  `watchdog.py:49` 의 `DEFAULT_TIMEOUT_SECONDS` 를 올리고 A2 를 다시 잰다.

**★ A 5개가 전부 `[x]` 가 되기 전에는 어머니 PC 에 올리지 않는다.**

## B. v0.3.0 우클릭 메뉴 (4항목 + 선행 1)

어머니가 **파일을 끌고 가지 않아도 되게** 하는 기능. 전부 `HKCU\Software\Classes` 라
관리자 권한이 필요 없고 설치 프로그램도 없다 — `cli.main()` 이 매 실행마다 자가 등록·자가 치유한다.

⚠️ 정직하게: Win11 에서는 "우클릭 한 번"이 아니라 **3클릭**이다. 줄어드는 것은 클릭 수가 아니라
**드래그라는 손 기술**과 창 두 개를 동시에 띄우는 일이다.

원본 설명: `WINDOWS-HANDOFF.md` 의 "v0.3.0 — 탐색기 우클릭 메뉴" 절.

### [ ] B0. (선행) exe 를 한 번 더블클릭한다

메뉴는 **exe 가 한 번 실행돼야** 생긴다(자가 등록). **순환 조건이라 이 줄이 없으면
"메뉴가 안 보인다"로 막힌다** — 릴리즈 노트에도 4번 항목으로 따로 적어 뒀다.

### [ ] B1. 메뉴가 탐색기에 실제로 보인다

- **하는 법** — .hwp 파일에 대고 오른쪽 버튼.
- **통과** — 변환 항목이 보인다.
- ★**레지스트리에 값이 있는 것과 메뉴에 뜨는 것은 다르다.** CI 는 레지스트리까지만 봤다(아래 표).

### [ ] B2. [프로그램에서 열기] 인가 [더 많은 옵션 표시] 인가

두 경로를 다 등록해 놨다. **어느 쪽이든 뜨면 통과 — 어느 쪽인지 기록하는 것이 이 항목의 목적이다.**

`확인 결과: ______________`

- **그 다음** — 확인한 쪽으로 `.github/release-notes.md` 의 안내 문장을 좁힌다.
  **지금은 양쪽을 다 적어 뒀다.** 어머니가 읽을 문장이라 "둘 중 하나일 거예요" 로 두면 안 된다.
- (상단 고정은 `IExplorerCommand` + app identity + **코드 서명**이 필요한데 우리한테 없다. 범위 밖.)

### [ ] B3. 띄어쓰기 든 파일명이 한 덩어리로 온다

- **하는 법** — `공문 최종 (수정).hwp` 를 **우클릭 메뉴로** 변환.
- **통과** — 정상 변환.
- **실패하면** — `cli.main` 의 `len(argv) > 1` 분기가 "한 번에 한 개씩"으로 거부한다.
  즉 **공백 든 파일만 조용히 실패**한다 — 재현 정보 없이 지원해야 하는 최악의 모양이라 꼭 재야 한다.
  (smoke 가 레지스트리의 `"%1"` 인용이 살아 있는 것까지는 확인했다. 그 뒤가 이 항목이다.)

### [ ] B4. .hwp 더블클릭이 여전히 한글로 간다

- **하는 법** — 아무 .hwp 나 더블클릭.
- **통과** — 한글이 열린다(우리 변환기가 아니라).
- **실패하면** — 어머니의 파일 연결을 가로챈 것이다. 즉시 롤백한다.

**롤백** — `python -c "from hwp2img import shell_menu; shell_menu.unregister()"`
또는 `HKCU\Software\Classes` 에서 `hwp2img.convert` · `.hwp\OpenWithProgids\hwp2img.convert` ·
`SystemFileAssociations\.hwp(x)\shell\hwp2img` 를 지운다. **확장자 키 자체는 지우지 않는다.**

워크플로가 실패하면 **태그만 남고 릴리즈는 안 생기며, 다시 돌리는 방법이 태그를 지우고
다시 미는 것뿐이다.**

```bash
git push origin :refs/tags/v0.3.0    # 원격 태그 삭제
git tag -d v0.3.0                    # 로컬 태그 삭제
# 원인을 고친 뒤 다시 tag + push
```

★**실제로 겪은 일이다.** 2026-08-25 03:37 에 v0.2.1·v0.2.2 태그의 release 런이
**3~4초 만에 실패**했다. 테스트가 깨진 게 아니라 GitHub **결제 차단**이었다
(run `32805891566`·`32805885222`, ANNOTATIONS: *"The job was not started because recent
account payments have failed…"*). 그 두 릴리즈는 08-24 에 이미 만들어져 있어서 손실이
없었을 뿐이다. **push 직후 Actions 탭을 꼭 확인하고, 4초짜리 실패면 로그가 아니라
ANNOTATIONS 를 봐라** — 그런 실패는 로그가 아예 안 남는다(`--log-failed` 가 `log not found`).

오른쪽 칸이 남은 부분이다.

|---|---|---|
| Windows 에서 테스트 154개 통과 | `test` 워크플로 (2026-09-19 재실행) | — |

## 손대지 마라

- **`output.py` 의 `open_in_explorer` 가 문자열 커맨드를 쓰는 이유** — argv 리스트로 바꾸는
  시도를 두 번 했고 둘 다 실패했다. `subprocess` 의 `list2cmdline` 이 `/select` 플래그를
  다시 따옴표로 감싸서 깨진다. "리팩터링" 하지 마라.
- **`Hwp.exe` 를 PID 로 강제 종료하는 코드** — A1 을 깨뜨린다(PID 재사용). A3 을 읽어라.
- **손상된 hwp 가 에러 없이 "성공"으로 처리되는 것** — 알려진 상태다. 알아볼 수 없는 PNG 가
  나올 뿐이라 의도적으로 남겨 뒀다. 고칠 거면 먼저 물어봐라.
- **자동 업데이트 · 배치(여러 파일 동시) 변환 · GUI 설정 화면 · macOS/Linux 지원** — 전부
  스코프 아웃이다. 어머니 한 명이 쓰는 프로그램이라 "있으면 좋은 것" 의 기준이 보통과 다르다.

## 교차검증 레인이 없는 세션이면

여긴 codex·cursor 같은 레인도, 강제 TDD 워크플로도 없다. 대신:

1. 고치기 **전에** `pytest` 로 기준선(154)을 잡는다.
2. 고친 뒤 다시 `pytest`. 실패가 있으면 그걸 고치기 전엔 다음으로 안 간다.
3. **Windows 전용 코드(COM·클립보드·레지스트리·watchdog)를 고쳤으면 유닛 테스트 통과로
   끝났다고 하지 마라.** 이 프로젝트의 유닛 테스트는 전부 페이크로 Windows API 를 흉내낸
   것이다(`FakeHwp` · `FakeClipboard` · 페이크 `winreg`) — 진짜 검증은 위 A·B·C 뿐이다.
4. 자기 diff 를 한 번 더 읽는다. "이 변경이 왜 필요했는지" 를 한 문장으로 못 하면 되돌린다.
